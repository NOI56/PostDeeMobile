# Gemini Model Separation for AI Editing and Captions

> **สถานะ (ทำเสร็จแล้ว):** อนุมัติแนวทางโดยผู้ใช้เมื่อ 30 กรกฎาคม 2026 และ
> นำเข้า `main` แล้ว ระบบปัจจุบันใช้ `gemini-3.5-flash-lite` สำหรับวางแผน
> ตัดต่อ และ `gemini-2.5-flash-lite` สำหรับคิดแคปชั่น ส่วนข้อความ “ปัจจุบัน”
> ในหัวข้อที่มาด้านล่างหมายถึงสถานะก่อนเริ่มงานนี้

## ที่มา

ปัจจุบันระบบกำหนด `gemini-2.5-flash-lite` เป็นทั้งโมเดลวางแผนตัดต่อ
และโมเดลคิดแคปชั่น ทำให้หน้าที่ของโมเดลทั้งสองส่วนไม่ชัดเจน
และการเปลี่ยนรุ่นในอนาคตมีโอกาสกระทบผิดส่วนได้

ผู้ใช้ต้องการให้:

- ระบบ **ตัดต่อด้วย AI** ใช้ `gemini-3.5-flash-lite`
- ระบบ **คิดแคปชั่นโพสต์** ใช้ `gemini-2.5-flash-lite` ต่อไป

`gemini-3.5-flash-lite` เป็นรหัสโมเดล Stable ตามเอกสารทางการของ Google:
<https://ai.google.dev/gemini-api/docs/models/gemini-3.5-flash-lite>

เอกสารการย้ายรุ่นกำหนดให้เอา sampling parameters ที่เลิกใช้ออกจาก
Gemini 3.5 Flash-Lite และหน้าสถานะโมเดลระบุว่า Gemini 2.0 Flash
ปิดให้บริการแล้ว:

- <https://ai.google.dev/gemini-api/docs/latest-model>
- <https://ai.google.dev/gemini-api/docs/deprecations>

## ข้อตัดสินใจ

แยกค่ารุ่นโมเดลให้เห็นชัดในทุกสภาพแวดล้อม โดยไม่ใช้ค่ารุ่นเดียวร่วมกัน:

| งาน | ตัวแปร | รุ่นโมเดล |
| --- | --- | --- |
| วิเคราะห์คำพูดและภาพเพื่อเลือกช่วงตัดต่อ | `GEMINI_EDIT_PLAN_MODEL` | `gemini-3.5-flash-lite` |
| คิดข้อความแคปชั่นสำหรับโพสต์ (โมเดลหลัก) | `GEMINI_CAPTION_MODEL` | `gemini-2.5-flash-lite` |

ค่าทั้งสองต้องถูกระบุชัดใน Production, Staging, ตัวอย่างไฟล์ตั้งค่า
และค่าเริ่มต้นในโค้ด เพื่อไม่ให้สภาพแวดล้อมหนึ่งเผลอใช้โมเดลผิดหน้าที่

## การทำงานหลังแก้

### ตัดต่อด้วย AI

1. ElevenLabs Scribe v2 ถอดเสียงและเวลาแต่ละคำตามเดิม
2. `gemini-3.5-flash-lite` วิเคราะห์บทพูดและภาพตัวอย่าง
   เพื่อเสนอช่วงที่น่าสนใจตามความยาวที่ผู้ใช้เลือก
3. กฎของ PostDee ตรวจความสมบูรณ์ของช่วงเปิด–จบ ความยาว
   และขอบคำไทยตามเดิม
4. ระบบสร้าง recipe ตรวจช่วงเงียบแยกจากการเลือกช่วงของ Gemini
   โดยใช้เวลาจาก transcript ตามเดิม
5. FFmpeg ตัดต่อและเรนเดอร์วิดีโอตามเดิม

### คิดแคปชั่นโพสต์

1. ระบบรับบริบทหรือข้อความที่ใช้คิดแคปชั่นตามเดิม
2. `gemini-2.5-flash-lite` เป็น Gemini รุ่นหลักที่สร้างตัวเลือกแคปชั่น
3. เอา fallback `gemini-2.0-flash` ที่ Google ปิดให้บริการแล้วออก
4. หาก Gemini 2.5 ยังล้มเหลวหลังลองใหม่ ให้เส้นทางเดิมลดระดับ
   ไปใช้เทมเพลตแคปชั่นในระบบ
5. API และหน้าจอแคปชั่นยังใช้รูปแบบเดิมทั้งหมด

## จุดที่จะเปลี่ยน

- เปลี่ยนค่าเริ่มต้นของ `GEMINI_EDIT_PLAN_MODEL` เป็น
  `gemini-3.5-flash-lite`
- คงค่าเริ่มต้นของ `GEMINI_CAPTION_MODEL` ที่
  `gemini-2.5-flash-lite`
- ระบุค่าทั้งสองอย่างชัดเจนใน `render.yaml` และ
  `render.staging.yaml`
- เอา `temperature` ออกจาก payload ของ Gemini เฉพาะสองเส้นทาง
  วางแผนตัดต่อ (transcript และ visual) เพราะ Google กำหนดให้
  Gemini 3.5 Flash-Lite เลิกใช้ sampling parameters เหล่านี้
- เอา `gemini-2.0-flash` ที่ปิดให้บริการแล้วออกจาก fallback
  ของ caption providers ทั้งแบบข้อความและคลิปจริง
- ทำให้ `.env.example` และเอกสารระบบตรงกับค่าที่ใช้งานจริง
- เพิ่มหรือแก้ tests ให้ตรวจว่าค่าของงานตัดต่อและงานคิดแคปชั่น
  แยกจากกันจริง

## สิ่งที่ไม่เปลี่ยน

- ไม่เปลี่ยน ElevenLabs Scribe v2
- ไม่เปิด Groq กลับมา
- ไม่เปลี่ยน API contract, โควตา Pro, การคิดนาที หรือแพ็กเกจ
- ไม่เปลี่ยนกฎเลือกช่วงของ PostDee
- ไม่เปลี่ยน FFmpeg หรือคุณภาพการเรนเดอร์
- ไม่เปลี่ยนหน้าจอมือถือในงานนี้
- ไม่เปลี่ยนค่า `temperature` ของระบบคิดแคปชั่นที่ยังใช้ Gemini 2.5
- ไม่ย้าย API key และไม่บันทึก secret ลง Git

## การรับมือเมื่อโมเดลมีปัญหา

ใช้เส้นทางสำรองเดิมของระบบ:

1. หากการวิเคราะห์ภาพล้มเหลว ให้ลองวางแผนจาก transcript
2. หาก Gemini ยังล้มเหลวหรือส่งข้อมูลไม่ถูกต้อง
   ให้ใช้กฎวางแผนแบบ deterministic ของ PostDee

การเปลี่ยนครั้งนี้จึงไม่ทำให้คลิปถูกทิ้งทันทีเมื่อโมเดลใหม่ตอบไม่ได้
และยังไม่เพิ่มหรือเปลี่ยนนโยบาย logging ในงานนี้

## แผนทดสอบ

ใช้แนวทาง test-first:

1. แก้ test ให้คาดหวัง `gemini-3.5-flash-lite`
   เฉพาะ `GEMINI_EDIT_PLAN_MODEL` และยืนยันว่า test ล้มก่อน
2. ยืนยันแยกต่างหากว่า `GEMINI_CAPTION_MODEL`
   ยังเป็น `gemini-2.5-flash-lite`
3. ทดสอบ payload ของ transcript planner และ visual planner ว่าใช้
   โมเดล 3.5, ส่ง structured JSON ตามเดิม และไม่มี `temperature`
4. ทดสอบ caption generator และ real-clip caption provider ว่าใช้
   Gemini 2.5 เป็นโมเดลหลัก ไม่มี fallback รุ่น 2.0 และยังลดระดับ
   ไปใช้เทมเพลตในระบบได้
5. ทดสอบค่าใน `env.ts`, `render.yaml` และ `render.staging.yaml`
   ว่าแยกสองหน้าที่ชัดเจน
6. แก้ค่าในโค้ดและไฟล์ deploy ให้ tests ผ่าน
7. รัน config tests, provider tests, API tests ทั้งหมด และ API build
8. หลังนำขึ้น Staging ให้ทดสอบ API จริงหนึ่งรอบ
   เพื่อยืนยันว่าบัญชี Google ที่ใช้อยู่เรียกโมเดล 3.5 ได้
9. ทดสอบคลิปไทยเดิมบน Pixel 8 และตรวจว่าหน้าคิดแคปชั่น
   ยังทำงานด้วยรุ่น 2.5 ตามเดิม

## เกณฑ์ผ่าน

- ทุกจุดของงานตัดต่อระบุ `gemini-3.5-flash-lite`
- ทุกจุดกำหนดค่าโมเดลหลักของงานคิดแคปชั่นระบุ
  `gemini-2.5-flash-lite`
- ไม่มี fallback ไป `gemini-2.0-flash` ที่ปิดให้บริการแล้ว
- ไม่มีจุดที่ใช้ตัวแปรโมเดลหนึ่งแทนอีกหน้าที่
- คำขอ Gemini 3.5 ของ transcript และ visual planner
  ไม่มี sampling parameters ที่เลิกใช้แล้ว
- config tests, API tests และ API build ผ่าน
- Staging เรียกโมเดลใหม่ได้จริงและเส้นทางสำรองยังทำงาน
- `README.md`, `ROADMAP.md`, `API.md`, `ARCHITECTURE.md`,
  `docs/GO_LIVE.md` และ `docs/RENDER_ENVIRONMENT_KEYS.md`
  ตรงกับระบบและไฟล์ deploy

## ความเสี่ยงและการย้อนกลับ

- บัญชีหรือพื้นที่ให้บริการของ Google อาจยังเรียกโมเดลใหม่ไม่ได้
  จึงต้องมีการทดสอบจริงบน Staging ก่อน Production
- ผลเลือกช่วงอาจเปลี่ยนจากรุ่น 2.5 แม้กฎตรวจหลังบ้านยังเหมือนเดิม
  จึงต้องใช้คลิปทดสอบชุดเดิมเพื่อเปรียบเทียบ
- หากเกิดปัญหา สามารถย้อนเฉพาะ
  `GEMINI_EDIT_PLAN_MODEL` กลับเป็น `gemini-2.5-flash-lite`
  โดยไม่กระทบระบบคิดแคปชั่นหรือการถอดเสียง
