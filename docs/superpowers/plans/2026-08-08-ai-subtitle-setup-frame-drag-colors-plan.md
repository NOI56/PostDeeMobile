## 1. สิ่งที่ตรวจพบในระบบปัจจุบัน

### 1.1 ภาพตัวอย่าง

- กล่องตัวอย่างในหน้าตั้งค่าซับยังเป็นพื้นหลังไล่สีจำลอง ไม่ใช่ภาพจากคลิปจริง
- แอปมี Video Player และแถบเลื่อนเลือกเวลาอยู่แล้วในหน้าทำภาพปก
- แอปมีตัวดึง JPEG ด้วย FFmpeg อยู่แล้ว แต่ตัวเดิมสร้างโฟลเดอร์ชั่วคราวและ
  ไม่มีเจ้าของคอยลบ จึงไม่เหมาะนำมาใช้ตรง ๆ ในหน้าที่ผู้ใช้เลื่อนไปมา
- ทางที่เร็วและปลอดภัยกว่าคือหยุด Video Player ไว้ที่เฟรมที่เลือก ไม่ต้องสร้าง
  ไฟล์ภาพใหม่ทุกครั้ง จึงไม่เพิ่มพื้นที่ดิสก์และตอบสนองทันกว่า

### 1.2 การขยับซับ

- ข้อมูลโปรเจกต์ซับมีตำแหน่ง X/Y แบบ 0–1 อยู่แล้ว
- แต่ Preview และตัวเรนเดอร์วิดีโอยังไม่ใช้ค่า X/Y จริง ปัจจุบันรองรับเพียง
  บน/กลาง/ล่าง
- หากทำเฉพาะการลากใน UI โดยไม่แก้ตัวเรนเดอร์ ไฟล์ที่ส่งออกจะไม่ตรงกับภาพ
  ที่ผู้ใช้เห็น จึงต้องแก้ครบทั้ง Preview, Draft, Subtitle Studio และ Export

### 1.3 สีข้อความและสีกรอบ

- Subtitle Studio มีชุดสีข้อความและสีกรอบพร้อมใช้อยู่แล้ว
- หน้าก่อน AI มีตัวแปรเก็บสีข้อความ แต่ปัจจุบันไม่ได้ใช้จริง
- คำขอไป API ยังบังคับเป็นสีขาว และ Preview ยังบังคับสีขาว/ขอบดำ
- ยังไม่มีตัวเลือกสีกรอบในหน้าก่อน AI

### 1.4 ความยาวต่อช่วงซับ

ป้ายปัจจุบันไม่ตรงกับการทำงานจริง:

| ป้ายที่ผู้ใช้เห็น | ระบบที่ส่งจริง | ข้อจำกัดเพิ่มเติม |
|---|---:|---|
| ไม่เกิน 8 ตัวอักษร | 1 คำ | คำเดียวอาจยาวเกิน 8 ตัวอักษร |
| ไม่เกิน 18 ตัวอักษร | 3–4 คำ | เปลี่ยนตามขนาดฟอนต์ และภาษาไทยมีเพดานเพิ่ม |
| ไม่เกิน 36 ตัวอักษร | 3–5 คำ | ภาษาไทยถูกจำกัดไม่เกิน 20 grapheme จึงแทบไม่ถึง 36 |

นอกจากนี้ Preview มีการย่อฟอนต์ให้พอดี แต่ระบบวัดความกว้างกับระบบ ASS ที่ใช้
สร้างวิดีโอยังใช้ฐานพิกัดไม่เหมือนกัน จึงต้องทดสอบให้ Preview และ Export ตรงกัน
จริง ไม่ตรวจเพียงว่าปุ่มถูกเลือก

## 2. พฤติกรรมใหม่ที่เสนอ

### 2.1 ภาพจริงหนึ่งเฟรมจากคลิป

หลังเลือกวิดีโอ:

1. แสดงเฟรมจริงจากกึ่งกลางคลิปเป็นค่าเริ่มต้น เพื่อเลี่ยงเฟรมเปิดที่มักเป็นสีดำ
2. ใต้ภาพมีเส้นเวลาเล็ก ๆ ให้เลื่อนไปยังเฟรมที่ต้องการ
3. ระหว่างลาก ใช้การ seek แบบเว้นช่วงประมาณ 100–120 ms เพื่อไม่ให้เครื่องค้าง
4. เมื่อปล่อยนิ้ว ให้หยุดตรงเวลาล่าสุดอย่างแม่นยำ
5. ภาพนี้ใช้เป็นพื้นหลังสำหรับลองซับเท่านั้น ไม่อัปโหลดและไม่สร้างไฟล์ภาพปก
6. หากอ่านคลิปไม่ได้ ให้แสดง Placeholder เดิม แต่ยังตั้งค่าซับและเริ่ม AI ได้

**ข้อแนะนำ:** ใช้ Video Player ที่หยุดอยู่บนเฟรม ไม่สร้าง JPEG ลงดิสก์ เว้นแต่
ภายหลังต้องส่งภาพนั้นไปใช้เป็นภาพปกจริง

### 2.2 ลากซับด้วยนิ้ว

- ผู้ใช้แตะข้อความซับใน Preview แล้วลากไปตำแหน่งใดก็ได้ในเฟรม
- ตำแหน่งเก็บเป็นจุดกึ่งกลาง X/Y ตั้งแต่ 0 ถึง 1 จึงไม่ผูกกับขนาดหน้าจอ
- ระบบกันซับออกนอก Safe Area โดยคำนวณจากขนาดข้อความจริง สีกรอบ และเงา
- ลากได้ทั้งแนวนอนและแนวตั้ง ไม่บังคับให้ติดเฉพาะบน/ล่าง
- มีปุ่มเล็ก `รีเซ็ตตำแหน่ง` กลับไปจุดมาตรฐานกลางล่าง
- ค่าเริ่มต้นยังเป็นกลางล่างประมาณ `(0.50, 0.88)` เพื่อให้ Draft เก่าดูเหมือนเดิม

### 2.3 สีข้อความและสีกรอบก่อน AI

เพิ่มสองแถวใต้ขนาดตัวอักษร:

- `สีข้อความ` — ใช้ชุดสีเดียวกับ Subtitle Studio
- `สีกรอบ` — ใช้ชุดสีเดียวกับ Subtitle Studio

เมื่อเลือกสี:

- Preview เปลี่ยนทันที
- ค่าถูกเก็บในชุดตั้งค่าและ Preset
- AI Recipe, Subtitle Studio, Preview ผลลัพธ์ และไฟล์ Export ใช้ค่าเดียวกัน
- หากสีข้อความกับสีกรอบใกล้กันมาก ให้แสดงคำเตือนเรื่องการอ่านยาก แต่ไม่บังคับ
  เปลี่ยนเอง

เวอร์ชันแรกใช้สีที่ผ่านการตรวจการมองเห็นแล้ว ไม่เพิ่มเครื่องมือผสมสีเต็มรูปแบบ
เพื่อลดความซับซ้อน หากภายหลังต้องการเลือกสีได้ทุกเฉด จึงค่อยเพิ่ม `สีเพิ่มเติม`

### 2.4 เอาตำแหน่ง บน/ล่าง ออกจากหน้า

- ลบหัวข้อ `ตำแหน่งซับ` และปุ่ม `บน/ล่าง` ออกจากหน้าก่อน AI
- ใช้การลากและปุ่มรีเซ็ตแทน
- ภายในข้อมูลยังอ่านค่า `top/bottom/middle` ของ Draft และแอปรุ่นเก่าได้
- เมื่อเปิดข้อมูลเก่า ระบบแปลงเป็น X/Y ดังนี้:
  - บน → `(0.50, 0.12)`
  - กลาง → `(0.50, 0.50)`
  - ล่าง → `(0.50, 0.88)`
- ไม่ลบข้อมูลเก่าทันที เพื่อป้องกัน Draft เดิมเสียหาย

### 2.5 แก้ความยาวซับให้ตรงความจริง

เปลี่ยนจากข้อความที่อ้าง “จำนวนตัวอักษร” เป็นจำนวนคำที่ระบบทำได้จริง:

| ตัวเลือกใหม่ | ค่าที่ส่งให้ระบบ | ความหมาย |
|---|---:|---|
| คาราโอเกะ | สูงสุด 1 คำ | เด่นทีละคำ |
| อ่านง่าย | สูงสุด 3 คำ | ค่าแนะนำสำหรับคลิปขายของทั่วไป |
| เนื้อหาครบ | สูงสุด 5 คำ | อ่านเนื้อหาได้ต่อเนื่องขึ้น |

กติกาความปลอดภัย:

- ไม่เกิน 5 คำต่อช่วงตามข้อตกลงเดิม
- ภาษาไทยยังต้องไม่เกิน 20 grapheme ต่อช่วง เพื่อไม่ให้ล้นจอ
- ห้ามตัดกลางคำหรือแยกสระ/วรรณยุกต์ออกจากพยัญชนะ
- หากคำเดียวกว้างเกินจอ ให้ลดขนาดฟอนต์อย่างมีขอบเขต แทนการตัดคำนั้นครึ่งหนึ่ง
- ระบบอาจทำช่วงให้สั้นกว่าค่าที่เลือกเพื่อป้องกันล้น แต่ห้ามยาวเกินค่าที่เลือก
- Preview และ Export ต้องใช้ฐานพิกัดและการวัดความกว้างเดียวกัน

ข้อความใต้ตัวเลือก:

> AI อาจใช้คำน้อยกว่าที่เลือกเพื่อไม่ให้ซับล้นจอ และจะไม่ตัดกลางคำ

## 3. โครงสร้างข้อมูลที่เสนอ

แยกข้อมูลเป็นสองชุดเพื่อไม่ส่งข้อมูล Preview ที่ไม่เกี่ยวกับ AI ไปยัง Server
และไม่ให้ Preset ของคลิปหนึ่งไปรบกวนอีกคลิปหนึ่ง

### 3.1 สัญญารูปแบบซับที่ใช้ร่วมกัน

สร้างข้อมูลกลาง เช่น `AiSubtitleStyleOptions`:

- `lengthPreset`: karaoke / readable / complete
- `maximumWordsPerCue`: 1 / 3 / 5
- `fontSizePreset`: small / medium / large
- `textColor`: `#RRGGBB`
- `outlineColor`: `#RRGGBB`
- `normalizedX`: 0–1
- `normalizedY`: 0–1

ข้อกำหนด:

- UI, Snapshot, Preset, API request, API response, Subtitle Project และ Renderer
  ต้องอ่านรูปแบบซับจากค่าชุดเดียวกัน
- API ตรวจสีและพิกัดก่อนรับค่า
- API ใหม่เพิ่มฟิลด์แบบ optional เพื่อให้แอปรุ่นเก่ายังทำงานได้
- ชื่อฟิลด์ใหม่กำหนดให้แน่นอนเป็น `subtitleOutlineColor`,
  `subtitleNormalizedX` และ `subtitleNormalizedY`
- เมื่อมีทั้ง X/Y ใหม่และ `subtitlePosition` เก่า ให้ X/Y ชนะเสมอ
- API ยังส่ง `subtitlePosition` ที่คำนวณจาก Y เพื่อให้แอปรุ่นเก่าอ่านได้ แต่ Mobile
  ใหม่ห้ามนำค่าดังกล่าวมา snap ทับ X/Y
- Decoder ของ `subtitle_project.dart` ต้องอ่าน Draft เก่าที่ไม่มี X/Y หรือสีกรอบ
  ได้ โดยใช้ค่า fallback ปลอดภัยแทนการบังคับว่าทุกฟิลด์ต้องมี

### 3.2 สถานะเฟรม Preview ในเครื่อง

เก็บ `previewFrameSeconds` แยกเป็นสถานะชั่วคราว ผูกกับ source fingerprint/path:

- ไม่ส่งเข้า API, Recipe, Draft หรือ Preset
- ยุบแล้วเปิดส่วนตั้งค่าซับใหม่ในคลิปเดิม ให้จำตำแหน่งเฟรมเดิม
- เปลี่ยนคลิป A → B ให้ reset เป็นกึ่งกลางของคลิป B
- ถ้าความยาวคลิปเปลี่ยน ให้ clamp เวลาใหม่เข้าในช่วงที่เล่นได้
- คลิปสั้นไม่เกิน 100 ms ใช้เวลา 0; คลิปที่ยังไม่รู้ความยาวให้รอ Controller
  initialize แล้วจึงเลือกกึ่งกลาง

### 3.3 สัญญาพิกัด Preview และ Export

- X/Y คือจุดกึ่งกลางของซับบน **พื้นที่ภาพวิดีโอจริงหลังอ่าน rotation แล้ว**
  ไม่ใช่ทั้งกล่อง Widget และไม่รวมแถบดำ
- Preview ต้องใช้อัตราส่วนและวิธี fit/crop เดียวกับไฟล์ที่ Renderer จะส่งออก
- Renderer ปัจจุบันรักษาอัตราส่วนต้นฉบับ ดังนั้น Preview รุ่นนี้ต้องแสดงทั้งเฟรม
  ตามอัตราส่วนจริง; ถ้าภายหลังเปิด Reframe 9:16 ให้ทั้ง Preview และ Renderer
  เปลี่ยนไปใช้ canvas 9:16 ชุดเดียวกัน
- Renderer รุ่นนี้ใช้ ASS logical canvas สูง 540 และคำนวณความกว้างตามอัตราส่วน
  ภาพหลังหมุน (เช่น 9:16 = 304×540, 9:20 = 243×540, 16:9 = 960×540)
  แล้วแปลง normalized X/Y ลง canvas เดียวกันทั้ง Preview/Export; การยืนยัน
  คลิปแนวนอนและ metadata หมุน
  เป็นเกณฑ์ Pixel 8 ก่อนถือว่าพร้อมใช้งาน
- Safe Area ใช้สัดส่วนฐานเทียบเท่า MarginX 24/304 และ MarginY 28/540
  รวมครึ่งหนึ่งของกรอบข้อความ สีขอบ และเงา
- ห้ามลากเข้า letterbox และต้องคำนวณ Safe Area ใหม่เมื่อข้อความจริง, ฟอนต์,
  ขนาดฟอนต์, ความหนาขอบ หรือเงาเปลี่ยน
- ซับเป็นส่วนหนึ่งของวิดีโอ จึงใช้ `TextScaler.noScaling` ทั้ง Preview และ Export
  เพื่อไม่ให้การตั้งค่าขนาดตัวอักษรของ Android ทำให้ไฟล์จริงต่างจากภาพตัวอย่าง

- ขนาดฟอนต์ไม่ทำให้ค่าที่แสดงกับค่าที่ส่งขัดกัน
- คำไทยที่มีวรรณยุกต์ไม่ถูกตัดกลาง grapheme
- คำเดียวยาวยังอยู่ครบคำ
- timing ที่เป็นเศษคำต้อง fail closed หรือใช้ boundary ที่ซ่อมแล้วเท่านั้น
- ทุก cue ที่ AI สร้างห้ามเกินค่าที่เลือก แม้เป็น fragmented timing, fallback,
  minimum-duration merge หรือ cue สุดท้าย
- Recipe และ Subtitle Project เก็บ `maximumWordsPerCue` ที่ผ่านการตรวจแล้ว
- API response แยกค่าที่ผู้ใช้ขอกับเพดานที่ระบบยอมรับอย่างชัดเจน
- การแก้ข้อความเองใน Subtitle Studio ถือเป็น manual override: ถ้าเกินค่าที่เลือกให้
  เตือนและเสนอแบ่งช่วง แต่ห้าม clip เงียบ ๆ; ถ้าลดถึงฟอนต์ขั้นต่ำแล้วยังไม่พอดี
  ต้องหยุด Export พร้อมข้อความให้แก้ ไม่ส่งไฟล์ที่ตัวอักษรถูกกิน

## 7. ความเสี่ยงและวิธีป้องกัน

- **Preview กับ Export ไม่ตรง:** ใช้ normalized X/Y และฐาน ASS เดียวกัน พร้อม
  content rect หลัง rotation/fit แบบเดียวกัน และ integration test จากเฟรมจริง
- **ลากซับออกนอกจอ:** clamp จากขนาดข้อความจริง รวมสีกรอบและเงา
- **คลิปหมุนผิดทิศ:** ทดสอบ metadata +90°/-90° บนอุปกรณ์จริง
- **เครื่องค้างตอนเลื่อนเฟรม:** throttle seek และไม่สร้าง JPEG ทุกครั้ง
- **Draft เก่าเสีย:** ฟิลด์ใหม่เป็น optional และมี mapping top/middle/bottom เดิม
- **ป้ายความยาวหลอกผู้ใช้:** เปลี่ยนเป็น 1/3/5 คำและทดสอบค่าตั้งแต่ UI ถึง Export
- **เสียโควตาซ้ำจากการเปลี่ยนสี/ตำแหน่ง:** แยก analysis cache ออกจาก presentation
  และทดสอบจำนวน provider/ledger call โดยตรง
- **ASS ล้มแล้วตำแหน่งหาย:** fallback เป็น ASS ที่ลดเอฟเฟกต์แต่คงตำแหน่ง ห้าม
