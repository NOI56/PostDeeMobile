# หน้าแอดมิน PostDee

รุ่นแรกอยู่ที่ `/admin` บน API เดิม มี 7 หน้า: ภาพรวม สมาชิก โพสต์
สิทธิ์ทดลอง ช่องทางที่เชื่อม รายงาน และประวัติผู้ดูแล
ระบบปิดอยู่โดยค่าเริ่มต้น และไม่มีบัญชีใดได้รับสิทธิ์จาก source code นี้

## วิธีใช้

1. เข้าด้วย Google ของโครงการ Firebase เดียวกับแอป บัญชีต้องมี UID อยู่ในรายการผู้ดูแลที่เซิร์ฟเวอร์
2. ค้นหาสมาชิกด้วยชื่อหรืออีเมล เปิดรายละเอียดเพื่อตรวจบัญชี แพ็กเกจที่ซื้อ
   โพสต์/ช่องทาง และการใช้โควตาเดือนปัจจุบัน (เดือน UTC เช่นเดียวกับแอป)
3. เจ้าของระบบเลือก Starter/Pro และ 7/14/30 วัน ใส่เหตุผล แล้วตรวจอีเมลกับรายการก่อนยืนยัน
   บัญชีที่มีทดลองอยู่ใช้ “ต่อเวลา” หรือ “ยกเลิกสิทธิ์ทดลอง”; ต่อเวลาได้ไม่เกิน 90 วันล่วงหน้า
4. ประวัติแสดงผู้ทำ เหตุผล และสิทธิ์ก่อน/หลัง รายการล่าสุดอยู่ก่อน
   หากเครือข่ายขาด ให้ใช้ “ตรวจผลคำขอเดิม” ซึ่งใช้หมายเลขคำขอเดิม หรือตรวจประวัติ
5. ผู้ดูแบบอ่านอย่างเดียวดูข้อมูลและส่งออกรายงานได้ แต่เปลี่ยนสิทธิ์ไม่ได้

สิทธิ์ทดลองใช้วันเริ่ม/หมดอายุของ PostDee แยกจากใบเสร็จ RevenueCat
ใช้แพ็กเกจที่สูงกว่าระหว่างสิทธิ์ซื้อที่ยังมีผลกับสิทธิ์ทดลอง ไม่รีเซ็ตโควตาที่ใช้ไปแล้ว
ไม่เรียกเก็บเงินหรือต่ออายุอัตโนมัติ และไม่ลดแพ็กเกจที่ซื้อไว้เมื่อหมดทดลองหรือยกเลิก
แพ็กเกจที่แสดงในแอปอัปเดตเมื่อโหลดข้อมูลสมาชิกใหม่ ไม่ใช่การ push เปลี่ยนหน้าจอทันที

หน้าโพสต์/ช่องทางเป็นการตรวจข้อมูล ไม่ส่งซ้ำ ไม่ลบ ไม่เชื่อม OAuth แทนลูกค้า
สถานะช่องทางเป็นข้อมูลที่บันทึก ไม่ใช่ผลตรวจสิทธิ์เผยแพร่แบบสด
สาเหตุโพสต์ใช้ข้อความที่ระบบยืนยันได้เท่านั้น ไม่เปิดข้อความดิบของผู้ให้บริการ

## รายงาน

- รายงานใช้ช่วงทดลอง **ล่าสุด** ของแต่ละบัญชี ช่วงเก่าดูในประวัติ
- นับแคปชัน AI, นาทีตัดต่อ และผลส่งที่บันทึกระหว่างเริ่มทดลองถึงเวลาปัจจุบัน/หมดอายุ/ยกเลิก
  รวมการใช้ทั้งบัญชีแม้มีแพ็กเกจซื้อทับซ้อนอยู่ จึงไม่ใช่การแยกต้นทุนที่เกิดจากทดลองล้วน ๆ
- `postUnits` ในรายงานคือจำนวนผลส่งต่อช่องทางที่บันทึกไว้ ไม่ใช่ใบเรียกเก็บของ PostPeer
  ส่วนหน่วยโพสต์ในรายละเอียดสมาชิกนับตามกติกาโควตาของแอป
- ไม่ใส่ต้นทุนเป็นศูนย์เมื่อยังไม่มีอัตรา ต้องกำหนด `ADMIN_COST_RATES_JSON` จึงจะคำนวณ USD ประมาณการ
  ไม่รวมค่าคงที่ Storage/Auth/ฐานข้อมูล/ภาษี และไม่ใช่ใบแจ้งหนี้
- แพ็กเกจที่ซื้อปัจจุบันไม่ใช้กล่าวอ้างว่าเป็นยอดเปลี่ยนจากทดลองเป็นลูกค้าเสียเงิน
- CSV ส่งออกครั้งละหน้ารายงาน (ไม่เกิน 50 บัญชี) พร้อมป้องกันสูตรสเปรดชีตจากข้อความที่นำเข้า

## เปิดใช้งานภายหลัง

ทำหลังได้รับอนุมัติ release และตรวจบัญชีเจ้าของแล้ว:

1. สำรองฐานข้อมูลตามขั้นตอนเดิม แล้วใช้ additive migrations `20261018090000_admin_trial_access`
   และ `20261018100000_reconcile_platform_enum_history` (เติม enum สองค่าที่ schema เดิมมีอยู่แล้ว)
   บนฐานข้อมูลเป้าหมายก่อนเปิด feature flag ไม่ต้องย้าย Firebase/Render/R2 ไป Supabase
2. ตั้ง `TRIAL_ACCESS_ENABLED=true` ให้ **ทั้ง API และ worker** ที่ใช้แพ็กเกจตัดสินสิทธิ์
   อย่าปิด flag นี้ระหว่างที่ยังมีทดลองอยู่ เพราะจะหยุดการใช้สิทธิ์ทดลองทั้งหมด
3. ใช้ `POST_STORE`, `SUBSCRIPTION_STORE`, `CAPTION_USAGE_STORE`, `AI_EDIT_USAGE_STORE=prisma`
   และ `DATABASE_URL` เดียวกับแอป ห้ามเปิด console ที่อ่านคนละชุดข้อมูล
4. ตั้ง `AUTH_PROVIDER=firebase`, `FIREBASE_PROJECT_ID` และ `FIREBASE_SERVICE_ACCOUNT_JSON`
   ของโครงการเดียวกัน Backend ตรวจ ID token และการเพิกถอนด้วย Firebase Admin
5. ตั้งตัวแปรด้านล่างบน API แล้วเปิด `ADMIN_CONSOLE_ENABLED=true`:

| ตัวแปร | ค่า |
| --- | --- |
| `ADMIN_CONSOLE_ORIGIN` | HTTPS origin ตรงกับ URL API ที่เปิด `/admin` ไม่มี path |
| `ADMIN_ENVIRONMENT` | `STAGING` หรือ `PRODUCTION` ให้ตรงระบบจริง |
| `ADMIN_OWNER_UIDS` | Firebase UID เจ้าของที่ยืนยันแล้ว คั่นหลายรายด้วย comma |
| `ADMIN_VIEWER_UIDS` | Firebase UID ผู้ดูข้อมูล คั่นด้วย comma; เว้นว่างได้ |
| `ADMIN_FIREBASE_WEB_CONFIG` | JSON เฉพาะ `apiKey`, `authDomain`, `projectId`, `appId` ของ Firebase Web App; ห้ามใส่ service account |
| `ADMIN_COST_RATES_JSON` | ไม่บังคับ; ตัวเลข `captionRequestUsd`, `editMinuteUsd`, `postUnitUsd` ตามต้นทุนที่ตรวจแล้ว |

6. เปิด Google sign-in และเพิ่ม hostname เป้าหมายใน Firebase Authorized domains
   ใช้บัญชีเจ้าของที่เปิดการยืนยันสองขั้นตอนของ Google และทบทวน UID ผู้ดูแลสม่ำเสมอ
7. อัปเดต Mobile ที่แยก `purchasedPlan` สำหรับยืนยันซื้อก่อนให้สิทธิ์ทดลองแก่ลูกค้า
   API จะกั้นแอปเก่าที่ไม่รองรับการยืนยันซื้อขณะมีสิทธิ์ทดลองสูงกว่าแพ็กเกจซื้อ
   จากนั้นทดสอบ Firebase popup, เจ้าของ/ผู้ดู/ลูกค้าทั่วไป, ให้สิทธิ์บัญชีทดสอบที่ระบุไว้,
   โหลดแพ็กเกจในแอป, ต่อเวลา/ยกเลิก และสิทธิ์แพ็กเกจซื้อ ก่อนใช้งานกับลูกค้าจริง

คำขอเปลี่ยนสิทธิ์ต้องเข้าสู่ระบบใหม่ภายใน 15 นาที ใช้ origin เดียวกันและ JSON header ของ console
หน้าแอดมินไม่เก็บ token แบบถาวร มี no-store/CSP และจำกัดอัตราคำขอ
ประวัติ trial เป็น append-only ใน API แต่จะ cascade ลบตามบัญชีเป้าหมายตามนโยบายลบบัญชีเดิม
ผู้มีสิทธิ์ฐานข้อมูลยังแก้ข้อมูลได้ตามสิทธิ์ DB; log นี้ไม่ใช่ที่เก็บหลักฐานที่แก้ไม่ได้ทางกายภาพ
