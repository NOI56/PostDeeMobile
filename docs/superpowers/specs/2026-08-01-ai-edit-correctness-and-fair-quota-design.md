# AI Editing Correctness and Fair Quota Design

> **สถานะเอกสาร:** ผู้ใช้อนุมัติแนวทางที่ 1 เมื่อวันที่ 1 สิงหาคม 2026
> เอกสารนี้เป็นแบบสำหรับงานรอบความถูกต้องและโควตา ยังไม่ได้หมายความว่า
> โค้ดตามแบบนี้ถูกพัฒนาแล้ว

## เป้าหมาย

ทำให้แต่ละตัวเลือกในหน้าตัดต่อด้วย AI ทำเฉพาะงานที่ผู้ใช้เปิดไว้ และเลือก
“ไม่ตัด” เมื่อหลักฐานไม่ชัดเจน โดยแก้สี่ปัญหาที่พบจากการทดสอบแยกบน Pixel 8:

1. การย่อความยาวเริ่มหรือจบกลางประโยคเมื่อไม่ได้เปิดซับ
2. การตัดช่วงเงียบลบเสียงพูดจริงและช่วงเปิดคลิป
3. การลดคำพูดซ้ำอ่านเวลาแบบตัวอักษรภาษาไทยไม่ได้และยังหักโควตา
4. การปรับสีอย่างเดียวส่งเสียงขึ้น AI และหักโควตาโดยไม่จำเป็น

รอบนี้ยึดหลัก **ความถูกต้องก่อนจำนวนช่วงที่ตัดได้** ถ้าระบบยืนยันความปลอดภัย
ไม่ได้ ระบบต้องเก็บช่วงนั้นไว้

## แนวทางที่พิจารณา

### แก้แบบ fail-closed บนอุปกรณ์และ API

**เลือกใช้แนวทางนี้** เพราะยังเปิดความสามารถให้ทดสอบได้ แต่เพิ่มหลักฐานเสียงจริง
ก่อนตัด ใช้เวลาคำไทยเฉพาะเมื่อประกอบกลับได้แน่นอน และตัดการใช้โควตาที่ไม่สร้าง
ผลลัพธ์ให้ผู้ใช้ ค่าใช้จ่ายและโครงสร้างพื้นฐานเพิ่มน้อยที่สุด

### ปิด silence และ repeated speech ชั่วคราว

ไม่เลือกเป็นแนวทางหลัก แม้ปลอดภัยและทำได้เร็ว เพราะผู้ใช้จะทดสอบสองความสามารถ
นี้ต่อไม่ได้ อย่างไรก็ตามใช้เป็นทางถอยกลับได้หาก Staging ยังพบการตัดคำพูดจริง

### ย้ายการตรวจเสียงทั้งหมดไป server/VAD ใหม่

ยังไม่เลือก เพราะเพิ่มการอัปโหลด งาน queue ค่า compute และความซับซ้อนในการดูแล
โดยยังไม่จำเป็นสำหรับการแก้ข้อผิดพลาดที่พิสูจน์ได้ในรอบนี้

## หลักฐานจากการทดสอบ

- โหมดความยาวอย่างเดียวทำผลลัพธ์ 30 วินาทีได้ตรง แต่เลือกช่วงประมาณ
  15–45 วินาทีและตัดหัว/ท้ายกลางประโยค
- โหมดซับอย่างเดียวผ่านเกณฑ์หลัก: ซับเป็นหนึ่งแถว อยู่ในขอบ และวรรณยุกต์ไทย
  ที่ตรวจไม่จมหรือซ้อน
- โหมดตัดช่วงเงียบลบช่วง 0–11.334 วินาที ทั้งที่มีเสียงจริง และอีกสามช่วง
  ทับคำพูด
- โหมดลดคำพูดซ้ำตอบว่าเวลาคำไม่ชัดพอทั้งคลิปเสียงรบกวนและคลิปเสียงชัด
  แต่แต่ละรอบยังลดโควตา
- โหมดปรับสีสดใส 60% ให้สีดีขึ้นจริง แต่ยังเรียก AI และลดโควตา ทั้งที่เป็น
  preset ที่เรนเดอร์บนเครื่องได้

## พฤติกรรมที่อนุมัติ

### ตัวเลือกเริ่มต้น

- ทุกความสามารถเสริมเริ่มปิดทั้งในแอปและ API
- API ต้องไม่เดาว่าผู้ใช้ต้องการซับ ตัดช่วงเงียบ ลดคำพูดซ้ำ หรือปรับสี
  เมื่อ client ไม่ส่งค่า
- การย่อความยาวอย่างเดียวเป็นคำขอที่ถูกต้อง โดยไม่เปิดความสามารถอื่นแฝง

### การย่อความยาว

- การตรวจขอบประโยคใช้ transcript เสมอ แม้ผู้ใช้ไม่ได้เปิดซับ
- transcript ที่ใช้ป้องกันขอบประโยคเป็นข้อมูลภายในเท่านั้น ไม่ทำให้ซับปรากฏ
- ขอบต้นและขอบท้ายต้องเลื่อนไปยัง cue/ประโยคสมบูรณ์ภายใน tolerance เดิม
  หนึ่งวินาที เมื่อมีข้อมูลเวลาที่เชื่อถือได้
- ถ้ารักษาความยาวเป๊ะกับประโยคสมบูรณ์พร้อมกันไม่ได้ ให้รักษาคำพูดสมบูรณ์
  และแสดงความยาวจริงของผลลัพธ์
- งานนี้ไม่เปลี่ยนระบบไฮไลต์สามวินาทีแรก ไม่จัดลำดับเรื่องใหม่ และไม่เพิ่ม
  คะแนน Hook ซ้ำกับ Gemini planner

### การตัดช่วงเงียบ

- ตัดได้เฉพาะช่วงภายในคลิป ห้ามตัดช่วงหัวและท้ายอัตโนมัติ
- ช่องว่างจาก transcript เป็นเพียง “ช่วงที่น่าตรวจ” ไม่ใช่คำสั่งตัด
- แอปตรวจซ้ำจากเสียงต้นฉบับบนเครื่องด้วย FFmpeg `silencedetect`
- ช่วงที่จะตัดต้องเป็นส่วนซ้อนกันของ:
  1. ช่องว่างภายในจาก transcript
  2. ช่วงเงียบที่เสียงบนเครื่องยืนยัน
  3. ช่วงที่ไม่ทับ word หรือ segment คำพูดที่ผ่านการตรวจ
- ค่าเริ่มต้นของตัวตรวจเสียงใช้ threshold แบบระมัดระวังที่ `-40 dBFS`
  และต้องเงียบต่อเนื่องอย่างน้อย 0.20 วินาที
- หลังหาจุดซ้อนกัน ให้เก็บ safety padding อย่างน้อยข้างละ 0.10 วินาที
  และทิ้งช่วงตัดที่เหลือสั้นกว่า 0.25 วินาที
- preset เดิมยังควบคุมช่องว่างขั้นต่ำจาก transcript:
  `natural=1.0`, `balanced=0.6`, `compact=0.4` วินาที
- ถ้าตรวจ waveform ไม่สำเร็จ ให้ไม่ตัดช่วงเงียบทั้งหมด ห้ามย้อนกลับไปใช้
  transcript gap โดยลำพัง

### การลดคำพูดซ้ำ

- backend รวม token ภาษาไทยระดับตัวอักษรให้เป็น semantic word ก่อนตรวจคำซ้ำ
- การรวมทำได้เฉพาะภายใน transcript segment เดียวกัน โดย:
  - normalize เป็น Unicode NFC
  - token ต้องเรียงเวลาและช่องว่างระหว่าง fragment ไม่เกิน 0.15 วินาที
  - ข้อความที่ต่อกันต้องตรงกับ semantic word จาก transcript แบบ exact match
  - เวลาเริ่มใช้ fragment แรกและเวลาจบใช้ fragment สุดท้าย
- ห้ามประดิษฐ์เวลาเมื่อ provider token หนึ่งก้อนครอบหลาย semantic words หรือ
  เมื่อประกอบข้อความกลับไม่ได้ครบ ระบบต้อง fail closed และไม่ตัด
- กฎตรวจคำซ้ำเดิมยังใช้ต่อ: ตัดอัตโนมัติเฉพาะคำ/วลีที่พูดติดกันและปลอดภัย
  เก็บ occurrence สุดท้าย และให้ผู้ใช้เปลี่ยนการเลือกได้ในหน้าตรวจผล
- คำที่พบบ่อยแต่กระจายคนละประโยคมีไว้แจ้งให้ผู้ใช้รู้ แต่ไม่ถูกเลือกตัดอัตโนมัติ

### การปรับสี

- ถ้าผู้ใช้เลือก “ปรับสี” อย่างเดียวและคงความยาวต้นฉบับ แอปตรวจสิทธิ์ Pro
  แล้วเรนเดอร์ preset บนเครื่องทันที
- เส้นทางนี้ไม่แยกเสียง ไม่อัปโหลดไฟล์ ไม่เรียก `/ai-edits/prepare`
  และไม่ลดนาที AI
- ถ้ามีการย่อความยาวหรือเปิดความสามารถ AI อื่น ให้ใช้ prepare หนึ่งครั้งตามเดิม
  แล้วใช้สีในขั้นเรนเดอร์บนเครื่อง
- ชื่อไฟล์ผลลัพธ์ต้องเป็นกลาง เช่น `_edited.mp4` ไม่ใช้ `_subtitled.mp4`
  เมื่อไม่ได้เปิดซับ
- ข้อความสถานะต้องไม่บอกว่า “กำลังเตรียมเสียงให้ AI” ในเส้นทางปรับสีอย่างเดียว

## โครงสร้างระบบ

### 1. API capability contract

`apps/api/src/modules/aiEdits/aiEditRecipe.ts` เปลี่ยนค่าเริ่มต้นของ capability
ทั้งหมดเป็น `false` และสร้างผลวิเคราะห์เฉพาะ capability ที่ร้องขอจริง
official mobile client ยังส่ง boolean ครบทุกตัวเหมือนเดิม การเปลี่ยนนี้ทำให้
legacy/incomplete request ปลอดภัยขึ้น

ฟิลด์ response `recipe.silenceRanges` ยังคงชื่อเดิมเพื่อไม่ทำลาย client เก่า
แต่สำหรับ client รุ่นใหม่มีความหมายเป็น transcript candidates ที่ต้องผ่าน
mobile waveform verifier ก่อนเป็น cut จริง

### 2. Transcript boundary guard

mobile mapper สร้างรายการ boundary segments จาก recipe transcript แยกจากรายการ
subtitle ที่จะเรนเดอร์ `ai_editing_screen.dart` ส่ง boundary segments ให้ตัวจัดขอบ
ต้นและท้ายเสมอ ส่วนการสร้างไฟล์ซับยังขึ้นกับ toggle `subtitle` เท่านั้น

### 3. Silence verifier

เพิ่มหน่วยย่อยใน mobile ที่มีหน้าที่เดียว:

- เรียก FFmpeg เพื่อตรวจช่วงเงียบของไฟล์ต้นฉบับ
- parse ผลลัพธ์เป็นช่วงเวลา
- intersect กับ transcript candidates
- ใส่ padding, ตัดช่วงสั้นทิ้ง และปฏิเสธช่วงที่ทับคำพูด

หน่วยนี้ต้องฉีด dependency ได้เพื่อทดสอบโดยไม่ต้องเปิด FFmpeg จริงใน widget test
และต้องคืนผลลัพธ์ว่างเมื่อ probe ล้มเหลว

### 4. Thai timed-token reconstructor

เพิ่ม pure function ฝั่ง API สำหรับประกอบ character-level timing เป็น semantic
word timeline แบบ exact-only แล้วส่ง timeline ที่ประกอบได้ให้ repeated-speech
detector เดิม การตรวจซับและ repeated speech แยกความรับผิดชอบกัน เพื่อไม่ทำให้
การยอมรับ timing แบบใหม่เปิด active-word subtitle ที่ยังไม่ปลอดภัยโดยอัตโนมัติ

### 5. Local-only color route

media strategy แยกผลลัพธ์ `local-render-only` ออกจาก `audio-only` เมื่อ
effective capability มีเฉพาะ color และไม่มี target shortening หน้าจอใช้ recipe
เฉพาะเครื่องสำหรับ preset ที่เลือก และไม่สร้าง metered API request

## ลำดับข้อมูล

### งานที่ต้องใช้ AI

1. ผู้ใช้เลือกวิดีโอ ความยาว และเปิดเฉพาะความสามารถที่ต้องการ
2. mobile ตรวจสิทธิ์และโควตา
3. mobile ส่ง M4A/visual proxy ตามความต้องการของ target planner เหมือนเดิม
4. ElevenLabs ส่ง transcript และ Gemini เลือก story window เมื่อมี target
5. API สร้างเฉพาะ candidates/ผลที่ผู้ใช้ร้องขอ
6. mobile จัดขอบประโยคจาก transcript แม้ไม่ได้เปิดซับ
7. ถ้าเปิด silence mobile ตรวจ waveform และใช้เฉพาะช่วงที่ยืนยันผ่าน
8. mobile เรนเดอร์ผลและเปิดหน้าตรวจผลงาน

### ปรับสีอย่างเดียว

1. ผู้ใช้เลือกวิดีโอ คงความยาวต้นฉบับ และเปิดเฉพาะปรับสี
2. mobile ตรวจสิทธิ์ Pro
3. mobile สร้าง local recipe จาก preset
4. mobile เรนเดอร์และเปิดหน้าตรวจผลงานโดยไม่ใช้โควตา AI

## กติกาโควตา

- ปรับสีอย่างเดียวแบบ local ไม่ใช้ AI minute
- repeat-only ที่ timing ใช้ไม่ได้และคืน `speechReduction.status=unavailable`
  ต้องไม่จองนาที เพราะผู้ใช้ไม่ได้ผลลัพธ์ที่ใช้งานได้
- ถ้า repeat ใช้ไม่ได้แต่คำขอเดียวกันสร้างซับ ย่อความยาว หรือวิเคราะห์ silence
  ได้สำเร็จ ให้คิดนาทีหนึ่งครั้งตามความยาวต้นฉบับตามกติกาเดิม
- การวิเคราะห์ silence สำเร็จแต่ไม่พบช่วงที่ควรตัดถือเป็นผลตรวจที่ใช้ได้และคิดนาที
- การ re-render จาก recipe ที่สำเร็จแล้วไม่เรียก provider และไม่คิดนาทีซ้ำ
- ความผิดพลาดก่อน provider/ก่อนสร้าง recipe ที่ใช้ได้ไม่จองนาทีเหมือนเดิม

## การรับมือข้อผิดพลาด

- waveform probe ล้มเหลว: เก็บเสียงทั้งหมด แสดงว่าไม่สามารถยืนยันช่วงเงียบได้
  และให้ลองใหม่ได้
- Thai token ประกอบไม่ได้: แสดงสถานะ “เวลาแต่ละคำไม่ชัดพอ” ไม่สร้าง cut
  และไม่คิดนาทีเมื่อเป็น repeat-only
- transcript ไม่มี boundary ที่เชื่อถือได้: ใช้ story window จาก planner โดยไม่เดา
  เวลาใหม่ และบอกความเสี่ยงใน review metadata สำหรับ QA
- local color render ล้มเหลว: ไม่คิดนาที AI เก็บต้นฉบับไว้ และให้ลองเรนเดอร์ใหม่
- ห้าม fallback จากกฎปลอดภัยไปใช้ cut ที่ตรวจไม่ผ่านโดยเงียบ ๆ

## แผนทดสอบ

ทุกพฤติกรรมใหม่ใช้ red-green-refactor และทดสอบเฉพาะระบบก่อนทดสอบรวม

### API

- request ที่ไม่ส่ง capabilities ได้ค่า false ทุกตัว
- request ที่เปิดเพียงหนึ่ง capability ไม่เปิดตัวอื่นแฝง
- silence candidates ไม่มี leading/trailing ranges
- character-level Thai tokens ประกอบกลับเป็น semantic words ได้เมื่อ exact match
- token ที่ข้ามคำ, เวลาไม่เรียง, gap เกินกำหนด หรือข้อความไม่ตรง fail closed
- repeat-only unavailable ไม่เพิ่ม usage ledger
- คำขอรวมที่มีผล AI อื่นสำเร็จคิดนาทีเพียงครั้งเดียว

### Mobile

- target length ใช้ transcript boundary แม้ subtitle=false
- boundary metadata ไม่สร้าง subtitle overlay
- silence verifier ใช้เฉพาะ intersection, padding และไม่ทับคำพูด
- probe failure ให้ช่วงตัดว่าง
- color-only original-duration เลือก local route และไม่เรียก upload/prepare
- color ร่วม target shortening ยังเรียก prepare หนึ่งครั้ง
- ชื่อไฟล์ใช้ `_edited` เมื่อไม่ได้เปิดซับ
- ทุก toggle เริ่มปิดและ request ส่ง false ครบ

### Pixel 8

ทดสอบแยกซ้ำด้วยคลิปชุดเดิม:

1. ความยาวอย่างเดียว: ไม่เริ่มหรือจบกลางประโยค
2. ซับอย่างเดียว: หนึ่งแถว อยู่ในขอบ วรรณยุกต์ไม่จม
3. silence อย่างเดียว: ช่วงเปิด/ท้ายอยู่ครบและไม่มีคำพูดถูกตัด
4. repeat อย่างเดียว: คลิปเสียงชัดตรวจคำซ้ำได้ และคลิปที่ timing ใช้ไม่ได้ไม่ถูกตัด
5. color อย่างเดียว: สีเปลี่ยนตาม preset, โควตาไม่ลด และไม่มีการอัปโหลด AI

## การนำขึ้นใช้งานและทางถอยกลับ

1. นำ API ที่ default capabilities เป็น false, ไม่สร้าง edge silence candidates
   และประกอบเวลาไทยแบบ exact ขึ้น Staging ก่อน พฤติกรรมนี้ปลอดภัยขึ้นสำหรับ
   client เก่าเพราะลดช่วงที่อาจถูกตัด
2. นำ mobile ที่มี transcript boundary guard, waveform verifier และ local color
   route ขึ้น Staging แล้วทดสอบแยกทีละตัวบน Pixel 8
3. ห้ามเปิด Production จนคลิป silence ชุดเดิมรักษาช่วงเปิดและคำพูดครบ
4. ถ้ายังพบการตัดคำพูดจริง ให้ปิด effective `silence` ใน mobile ชั่วคราว
   โดยไม่ย้อนระบบซับ ความยาว repeated speech หรือ color
5. ถ้า token reconstruction ให้ผลคลุมเครือ ให้ปิดเฉพาะ automatic repeat cuts
   และคงรายการตรวจพบแบบอ่านอย่างเดียว

การ rollback ต้องไม่คืนค่า server defaults ที่เปิด subtitle/silence เอง และต้องไม่
กลับไปใช้ transcript gaps เป็น cut โดยตรง

## นอกขอบเขตรอบนี้

- แก้ encoder fallback จาก H.264 เป็น MPEG-4 Part 2
- รักษา 30fps และลดขนาดไฟล์ preview/export
- limiter เพื่อให้ true peak ไม่เกินประมาณ -1 dBTP
- ปรับ timebase รอยต่อภาพ/เสียงให้ตรงกว่าเดิม
- ปรับ timeout/ข้อความผิดพลาดของการตรวจสิทธิ์ Pro ครั้งแรกหลังเปิด Emulator
- เพิ่ม visual AI, Hook สามวินาที, beat sync หรือความสามารถที่ยังล็อกอยู่

งาน codec, fps, ขนาดไฟล์, audio peak และ A/V sync เป็นงาน renderer quality
ชุดถัดไปทันทีหลังชุด correctness ผ่าน Pixel 8 เพื่อให้สาเหตุและผลทดสอบไม่ปนกัน

## เกณฑ์สำเร็จ

- ไม่มี capability ใดเปิดเองเมื่อผู้ใช้ไม่ได้เลือก
- คลิปย่อไม่เริ่มหรือจบกลางคำ/กลาง cue เมื่อมี transcript timing ที่เชื่อถือได้
- silence mode ไม่ตัดหัว/ท้าย ไม่ตัดทับคำพูด และไม่ใช้ transcript gap ลำพัง
- repeated speech ใช้ character-level Thai timing ได้เมื่อประกอบกลับแบบ exact
  และไม่ตัดเมื่อพิสูจน์ไม่ได้
- repeat-only unavailable และ color-only local ไม่ลดโควตา AI
- ผู้ใช้ยังแก้การเลือกคำซ้ำได้ก่อนยอมรับผล
- ซับอย่างเดียวที่ผ่านแล้วไม่ถดถอย
- API tests, API build, Flutter focused/full tests, Flutter analyze, Android APK
  และ Pixel 8 isolated smoke matrix ผ่านก่อนนำขึ้น Staging
